### 1. `modelTier: 'inherit'` (模型分级与成本控制)
在一个复杂的多智能体系统中，让所有节点都跑最聪明但也最贵的大模型（比如 GPT-4o 或 Claude 3.5 Sonnet）是极其烧钱的。
* **工程实践**：大老板（Supervisor）和程序员（Coder）负责复杂的逻辑规划和代码生成，必须用顶级模型（`Tier 1`）。但是像 Explorer（仅仅是调工具列出文件）或者 Verifier（只是判断测试输出是 Pass 还是 Fail），完全可以使用便宜快速的小模型（如 GPT-4o-mini，`Tier 2`）。
* **你的设定**：`'inherit'` 意味着当前这个 Verifier 没有强制指定降级，它继承了 orchestrator 中配置的全局默认模型。这为你未来进行精细化的 API 成本控制预留了完美的接口。

### 2. `isolation: 'tmp-only'` (沙箱物理隔离)
这是防御 Agent “发疯”的最强护城河。
* **危险场景**：Verifier 的任务是找 Bug。如果它拥有操作宿主机源码的权限，它可能会在执行测试时，一怒之下把报错的源文件给删了。
* **工程实践**：`'tmp-only'` 表示这个智能体处于一个**只读源码，但只能在临时目录写数据**的沙箱（Sandbox）中。它在底层获取 `CodeToolRegistry` 工具时，工具注册表会读取这个属性，强行把它请求的路径全部映射到项目根目录下的 `.ycc/tmp` 文件夹中。这样它怎么折腾都不会破坏你的项目源码。

### 3. `criticalReminder` (克服大模型的“遗忘曲线”)
在 LangGraph 中，随着大模型跟工具反复交互，对话历史（Context）会变得非常长。
* **痛点**：大模型存在严重的**“近因效应”（Recency Bias）**。如果在长对话的开头（System Prompt）告诉它“严禁修改源码”，在对话进行了 10 轮之后，它极大概率会忘得一干二净，开始胡作非为。
* **工程实践**：`criticalReminder` 是一种“系统级外挂”。我们在底层 `workerGraph.ts` 组装 Prompt 的最后一刻，会把这段强警告**强制追加到 User 消息的最后面，或者紧贴着最新的那条消息**。这就像在每次大模型闭眼思考前，都在它耳边大吼一句：“这是纯验证任务！必须执行命令！”保证它绝对不跑偏。

### 关于未开发的杀手锏工具：`bash_execute` 和 `write_tmp_file`

你的判断完全正确，这两个工具是我们接下来要给 Verifier 装备的“武器”。

在自动化软件工程（SWE-Agent 的核心思想）中，**“不运行的代码就是无效的代码”**。
一个真正的验证专家（Verifier）的工作流应该是这样的：
1. **[读取]** 看了 Coder 写的计算器代码。
2. **[写测试]** 使用 `write_tmp_file` 在 `.ycc/tmp/test_calc.js` 里写一段测试用例代码。
3. **[执行]** 使用 `bash_execute` 运行工具（相当于在终端执行 `bun run .ycc/tmp/test_calc.js`）。
4. **[判决]** 拿到终端标准输出（stdout/stderr），分析报错信息，然后打回给大老板或者宣告任务成功。

你之前的设计非常有前瞻性，我们随时可以将这两个工具的实现提上日程！
