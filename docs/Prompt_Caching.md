这是一个非常敏锐的问题！“命中缓存”（Prompt Caching / 提示词缓存）是 2024 年以来大模型 API（如 Anthropic Claude、OpenAI API 以及 OpenRouter 上的诸多模型）推出的一项**极其重要且最能省钱**的底层技术。

简单来说，**“命中缓存”就是让大模型记住它刚刚读过的内容，不要每次都重新读一遍，从而为你节省 50%~90% 的 Token 费用，并成倍缩短响应时间。**

为了让你彻底明白我们在架构设计里为什么要搞“动静分离（DYNAMIC_BOUNDARY）”，我为你拆解一下它的底层运作规则：

### 1. 大模型是如何“阅读”的？(KV Cache 原理)
大模型没有人类那样的“长记忆”。每次你给它发 API 请求时，它都必须把整个上下文（包括几千字的 System Prompt、之前的对话历史）从头到尾重新计算一遍，转换成数学矩阵（这在底层被称为 KV Cache）。
这个计算过程**非常耗费算力**，所以模型厂商对你的“输入 Token”收取的费用是很昂贵的，而且上下文越长，模型反应越慢（Time-To-First-Token 延迟变高）。

### 2. 什么是“提示词缓存” (Prompt Caching)？
为了解决这个问题，大模型厂商推出了一项机制：**如果在你的新请求中，开头的一部分内容与最近几分钟内的某个请求完全一模一样，大模型就会直接“抄作业”（直接调取内存里的计算结果），不再重新计算这部分内容。** 这就叫“命中缓存”。

命中缓存的收益极大：
* **费用暴跌**：被缓存的 Input Token 价格通常会打骨折（例如 Claude 3.5 Sonnet 的缓存 Token 价格比未缓存的便宜 **90%**）。
* **速度狂飙**：几万字的背景代码，如果是缓存命中的，大模型几乎在 1 秒内就能开始吐出回复。

### 3. 极其苛刻的“前缀匹配”规则 (Prefix Matching)
这是最关键的坑，也是我们做架构升级的根本原因：**缓存必须是从 Prompt 的绝对开头（第一个字符）开始算起，且必须连续一致！一旦遇到一个不一样的字，缓存链条当场断裂，后面的内容全作废。**

#### ❌ 反面教材（你目前的代码架构）：
假设你把动态变量写在了提示词开头：
* **第一轮对话 API 发送：** `【当前时间：上午10:00】你是资深程序员。你要遵守以下1000字的代码规范...`
* **第二轮对话 API 发送：** `【当前时间：上午10:01】你是资深程序员。你要遵守以下1000字的代码规范...`

**结果**：大模型读到“01”的时候，发现和上一次的“00”不一样。**缓存链条在第10个字符处瞬间断裂！** 后面那 1000 字的“代码规范”虽然完全没变，大模型也必须按全价扣费，并且重新计算。你的钱白白烧掉了。

#### ✅ 正确架构（Claude Code 的做法 / 我们规划的方案）：
引入动静分界线（`DYNAMIC_BOUNDARY`），把永远不变的内容顶在最前面：
* **第一轮对话 API 发送：** `[静态区] 你是资深程序员。你要遵守以下1000字的代码规范... [动态区] 当前时间：上午10:00`
* **第二轮对话 API 发送：** `[静态区] 你是资深程序员。你要遵守以下1000字的代码规范... [动态区] 当前时间：上午10:01`

**结果**：大模型一对比，发现前面 1000 字的 `[静态区]` **一字不差**！直接宣告**命中缓存**！这 1000 字瞬间加载并按 1 折计费。它只需要花原价计算最后那几个代表时间的动态 Token 即可。

### 总结：为什么这对你的 Code CLI 至关重要？

在你的项目里，Explorer（探路者）和 Coder（程序员）在执行任务时，会在 `workerGraph.ts` 的深层子图中疯狂地**循环调用工具**（比如先 `list_files`，再 `read_file`，再 `grep_search`）。

这意味着，如果在完成一个需求的过程中，大模型在后台默默发起 10 次 API 请求，如果没有设计好缓存命中：
* 那一大段告诉它“绝对不准用 `cat`，必须用 `read_file`”、“不要过度工程”的 System Prompt 会被全价计费 **10 次**。

当我们把 `AgentDefinition` 重构，将身份、规则、工具说明抽离为绝对不变的**静态段**，将你的 `$PWD`、 Git 状态放在分界线之后的**动态段**，你的整个 CLI 工具在使用时将变得**极其省钱，且响应极快**。

这就是“提示词工程（Prompt Engineering）”进入到工业落地阶段的魅力：**我们不仅要为 AI 的智商写 Prompt，还要为系统架构的性能和成本写 Prompt。**
